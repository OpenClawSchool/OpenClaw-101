> **대상:** OpenClaw School 2차시 수강생
> **분량:** 하루 20~30분
> **전제:** 옵시디언 볼트(Vault)는 **오픈클로가 설치된 서버**에 있습니다. 여러분은 옵시디언 앱을 직접 조작하지 않고, **채팅으로 에이전트에게 지시**해서 모든 미션을 수행합니다.
> **목표:** 6일 뒤, 에이전트를 통해 나의 Knowledge Base를 자유자재로 만들고, 엮고, 점검하고, 정리할 수 있다.

## 시작하기 전에: 역할 분담

이 미션의 핵심은 옵시디언 조작법이 아니라 **"에이전트에게 지식 관리를 시키는 법"**입니다. 역할은 명확합니다.

| 역할 | 담당 | 하는 일 |
| :-- | :-- | :-- |
| **나 (전문가)** | 방향과 검수 | 무엇을 기록할지 결정, 나의 경험 제공, 결과물 검수 |
| **오픈클로 (실행자)** | 실행 | 노트 생성·수정, 링크 연결, 태그 정리, 구조 분석 |

에이전트가 아무리 잘 써줘도 **Example(실전 사례)의 재료는 나의 경험**에서 나와야 합니다. 그래야 세상에 하나뿐인 전문가 KB가 됩니다.

### 사전 준비 (2차시 실습에서 완료한 상태, 서버 사용자는 안해도 됨)

아직 안 되어 있다면 에이전트에게 순서대로 지시하세요.

```
옵시디언 설치해줘
```
```
옵시디언 CLI 설치해줘
```
```
현재 워크스페이스를 옵시디언 기본 볼트 폴더로 설정해줘
```

## Day 1 — 마크다운 문법: 에이전트의 결과물을 읽는 눈 기르기

### 오늘의 개념

서버의 볼트에서 모든 노트는 마크다운(.md)으로 저장됩니다. 에이전트가 노트를 대신 써주더라도, **결과물이 잘 쓰였는지 판단하고 고치라고 지시하려면** 내가 마크다운을 읽을 줄 알아야 합니다. 오늘은 에이전트가 만든 노트를 받아보며 문법 6종을 익힙니다.

| 문법 | 쓰는 법 | 역할 |
| :-- | :-- | :-- |
| 제목 | `# 큰제목` `## 중간제목` | 문서의 뼈대 |
| 강조 | `**굵게**` `*기울임*` | 핵심 표시 |
| 목록 | `- 항목` / `1. 항목` | 나열 |
| 인용 | `> 인용문` | 인용·다짐 |
| 코드 | `` `코드` `` / ` ``` ` 블록 | 명령어·예시 |
| 표 | `\| 열1 \| 열2 \|` | 비교·정리 |

### 미션 (20~30분)

1. 에이전트에게 자기소개 노트 생성을 지시합니다.
   ```
   볼트에 '자기소개.md' 노트를 만들어줘.
   내용: 이름과 전문 분야(제목), 이 분야를 선택한 이유(내 다짐을 인용문으로),
   내가 아는 것 3가지와 배우고 싶은 것 3가지(목록), 학습 계획(표).
   제목·강조·목록·인용·코드·표 문법을 모두 사용해줘.
   ```
2. 결과를 확인합니다.
   ```
   자기소개.md 원본 마크다운 그대로 보여줘
   ```
3. 원본을 읽으며 문법 6종이 각각 어디에 쓰였는지 찾아봅니다. 마음에 안 드는 부분은 **직접 고치지 말고 수정을 지시**합니다.
   ```
   자기소개.md에서 학습 계획 표에 '기간' 열을 추가하고, 다짐 인용문을 더 짧게 다듬어줘
   ```

> **💡 TIP:** "원본 마크다운 그대로 보여줘"는 6일 내내 쓰는 검수 명령입니다. 렌더링된 모양이 아니라 기호(`#`, `-`, `|`)가 보이는 원본을 읽는 습관을 들이세요.

### 완료 체크리스트

- [ ] 문법 6종이 모두 쓰인 자기소개 노트 생성
- [ ] 원본 마크다운에서 6종 문법 위치를 직접 찾아냄
- [ ] 수정 지시 → 반영 확인 사이클 1회 이상 경험

## Day 2 — AI 친화적 노트: 좋은 초안을 뽑는 지시법

### 오늘의 개념

에이전트에게 "노트 써줘"라고만 하면 평범한 글이 나옵니다. 2차시에서 배운 **4단 구조**를 지시문에 넣어야 AI 친화적 노트가 나옵니다.

| 단계 | 필수 요소 | 채우는 사람 |
| :-- | :-- | :-- |
| **Topic** | 명확한 제목 | 나 (질문 선정) |
| **Concept** | 쉬운 개념 정의 | 에이전트 초안 → 나 검수 |
| **Example** | 실전 사례 | **나의 경험** (에이전트가 지어내면 안 됨) |
| **Checklist** | 검증 방법 | 에이전트 초안 → 나 검수 |

그리고 노트를 만들기 전에, 노트가 살게 될 집부터 짓습니다. **PARA 문서관리기법** — 노트를 '주제'가 아닌 '행동' 기준으로 나누는 방법으로, **P**rojects(기한 있는 일), **A**reas(계속 관리할 영역), **R**esources(참고 자료), **A**rchives(보관소) 4개 폴더를 씁니다. 오늘은 폴더만 만들어 두고, 본격적인 활용은 Day 6에서 다룹니다.

### 미션 (20~30분)

1. PARA 폴더 4개를 만들게 하고, 결과를 확인합니다.
   ```
   옵시디언 파라 기법 폴더 만들어줘
   ```
   ```
   볼트의 파라 기법 폴더 구조를 트리로 보여줘
   ```
2. 나의 전문 분야에서 **가장 자주 받는 질문 2개**를 고릅니다. (2차시 질문 로드맵 20개에서 골라도 좋습니다.)
3. 질문 하나당 노트 하나씩, 에이전트에게 지시합니다. **Example 재료는 내가 채팅으로 직접 제공**하는 것이 포인트입니다. 전문 분야 지식은 계속 관리할 영역이므로 **Areas 폴더**에 저장하게 합니다.
   ```
   '영어 발음 교정 3단계.md' 노트를 4단 구조(Topic-Concept-Example-Checklist)로 만들어서
   Areas 폴더에 저장해줘. 각 단계는 ## 헤더로 구분해줘.
   Example에는 다음 내 경험을 정리해서 넣어줘:
   "작년에 성인 수강생 한 분이 th 발음이 안 됐는데, 혀 위치 사진을 보여주고
   하루 5분 거울 연습을 시켰더니 3주 만에 교정됐다."
   ```
4. 결과를 원본으로 받아 검수합니다. 에이전트가 Example을 부풀리거나 지어낸 부분이 있으면 사실대로 고치게 합니다.
   ```
   Example에서 내가 말하지 않은 내용은 빼고, 내 경험 그대로만 남겨줘
   ```
5. 같은 방식으로 두 번째 노트를 완성합니다.

> **💡 TIP:** 에이전트가 그럴듯하게 지어낸 사례는 KB의 독입니다. 3차시에서 이 KB로 답변하는 에이전트가 **없는 사실을 손님에게 말하게 됩니다.** Example 검수에 시간의 절반을 쓰세요.

### 완료 체크리스트

- [ ] PARA 폴더 4개 생성 및 폴더 구조 확인
- [ ] 4단 구조 노트 2개를 Areas 폴더에 완성
- [ ] Example이 100% 나의 실제 경험으로 채워짐
- [ ] 지어낸 내용 검수·수정 사이클 경험

## Day 3 — [[링크]]: 지식망을 엮으라고 시키기

### 오늘의 개념

옵시디언의 힘은 폴더가 아니라 **링크**입니다. 노트 안의 `[[노트제목]]`이 두 지식을 연결하고, 링크가 쌓이면 KB가 낱장 문서가 아닌 그물망이 됩니다. 에이전트는 볼트 전체를 읽을 수 있으므로 **"서로 관련된 노트를 찾아 연결하라"**는 위임이 가능합니다. 단, 어떤 연결이 의미 있는지는 전문가인 내가 판단합니다.

### 미션 (20~30분)

1. 지식의 대문 역할을 할 **허브 노트**를 만들게 합니다.
   ```
   '_허브.md' 노트를 만들어줘. 볼트의 모든 노트를 [[링크]]로 나열하고,
   각 링크 옆에 그 노트가 어떤 지식인지 한 줄 설명을 달아줘.
   ```
2. 노트끼리의 연결을 위임하고, 근거를 보고받습니다.
   ```
   볼트의 노트들을 읽고 서로 관련 있는 개념끼리 본문에 [[링크]]를 걸어줘.
   어떤 노트를 왜 연결했는지 목록으로 보고해줘.
   ```
3. 보고를 읽고 **어색한 연결은 빼고, 빠진 연결은 추가**하게 합니다. (이 판단이 오늘 미션의 핵심입니다.)
4. 앞으로 써야 할 지식을 예약합니다.
   ```
   아직 노트가 없는 주제 중 내 분야에 꼭 필요한 것들을
   허브 노트에 [[미작성 노트]] 링크로 추가해줘
   ```

> **💡 TIP:** 존재하지 않는 노트로의 `[[링크]]`는 깨진 게 아니라 **"앞으로 채울 지식의 예약석"**입니다. Day 5에서 이 예약석들이 빈틈 지도가 됩니다.

### 완료 체크리스트

- [ ] 허브 노트 완성 (전체 노트 링크 + 한 줄 설명)
- [ ] 에이전트의 연결 보고를 검수하고 최소 1건 수정 지시
- [ ] 미작성 노트 예약 링크 3개 이상

## Day 4 — 태그: 분류 체계를 세우고 위임하기

### 오늘의 개념

**링크**가 노트 사이의 '관계'라면 **태그**(`#태그`)는 노트의 '속성'입니다. 태그 체계 없이 에이전트에게 "태그 달아줘"라고 하면 매번 다른 태그를 만들어 뒤죽박죽이 됩니다. 순서가 중요합니다 — **내가 체계를 정하고, 적용을 위임합니다.** 이렇게 만든 체계표는 에이전트가 앞으로 계속 참조하는 규칙이 됩니다.

### 미션 (20~30분)

1. 태그 체계 초안을 함께 잡습니다. 최종 결정은 내가 합니다.
   ```
   내 볼트의 노트들을 보고 어울리는 태그 체계를 5~8개로 제안해줘.
   태그명과 용도를 표로 보여줘.
   ```
2. 제안을 다듬어 확정하고, 규칙 노트로 저장하게 합니다.
   ```
   방금 정한 태그 체계를 '태그 체계.md' 노트로 저장해줘.
   앞으로 노트를 만들거나 수정할 때 항상 이 체계표의 태그만 사용해줘.
   ```
3. 전체 적용을 위임합니다.
   ```
   볼트의 모든 노트에 태그 체계표에 맞는 태그를 달아줘.
   노트별로 어떤 태그를 왜 달았는지 보고해줘.
   ```
4. 태그로 검색이 되는지 확인합니다.
   ```
   #사례 태그가 달린 노트 목록 보여줘
   ```

> **💡 TIP:** 태그가 10개를 넘으면 에이전트도 사람도 헷갈립니다. 새 태그가 필요해 보이면 먼저 "기존 태그로 커버 안 되는지" 에이전트에게 물어보세요.

### 완료 체크리스트

- [ ] 태그 체계표 확정 및 노트로 저장 (5~8개)
- [ ] 전체 노트 태그 적용 + 보고 검수
- [ ] 태그 검색으로 노트 필터링 성공

## Day 5 — 지식망 분석: 에이전트로 빈틈 찾기

### 오늘의 개념

옵시디언 앱의 그래프 뷰는 지식망을 눈으로 보는 기능이지만, 서버 환경에서는 화면 대신 **에이전트의 분석 능력**을 씁니다. 에이전트는 볼트 전체의 링크 구조를 읽고 다음을 찾아낼 수 있습니다.

- **고아 노트(Orphan):** 어떤 노트와도 연결되지 않은 노트 → 연결 필요
- **빈틈(Gap):** 예약 링크로 남아 있거나, 있어야 하는데 없는 지식 → 작성 필요

지식망 분석은 "내가 무엇을 아는가"가 아니라 **"내가 무엇을 모르는가"**를 드러내는 작업입니다.

### 미션 (20~30분)

1. 볼트 분석 리포트를 요청합니다.
   ```
   볼트 전체의 링크 구조를 분석해서 리포트를 만들어줘.
   1) 전체 노트 수와 링크 수
   2) 어떤 노트와도 연결되지 않은 고아 노트 목록
   3) 링크만 있고 아직 작성 안 된 미작성 노트 목록
   4) 내 전문 분야 관점에서 빠져 있다고 보이는 주제 3가지
   ```
2. 고아 노트를 연결하게 합니다.
   ```
   고아 노트들을 관련 있는 노트나 허브 노트에 링크로 연결해줘
   ```
3. 리포트의 '빠진 주제' 중 **손님 질문이 가장 많을 것 하나**를 내가 고르고, Day 2 방식(4단 구조 + 나의 경험 제공)으로 신규 노트 1개를 작성시킵니다.
4. 분석 리포트는 노트로 남겨 성장 기록으로 삼습니다.
   ```
   오늘 분석 리포트를 '볼트 성장일지.md'에 날짜와 함께 기록해줘
   ```

> **💡 TIP:** 이 분석은 언제든 반복할 수 있습니다. "볼트 분석해서 성장일지에 추가해줘" 한 줄이면 되니, 미션이 끝난 뒤에도 주 1회 습관으로 만들어 보세요.

- [ ] 고아 노트 0개 달성
- [ ] 빈틈을 메운 신규 노트 1개 (Example은 나의 경험)
- [ ] 성장일지 노트 생성

## Day 6 — PARA 재편: 볼트 구조 개편 위임하기

### 오늘의 개념

마지막 날은 쌓인 노트를 **행동 기준**으로 재배치합니다. 2차시 보충 자료의 PARA 기법입니다.

- **P (Projects):** 목표와 기한이 있는 일 (예: 전문가 에이전트 만들기)
- **A (Areas):** 기한 없이 계속 관리할 영역 (예: 나의 전문 분야)
- **R (Resources):** 관심 있는 학습 주제·참고 자료
- **A (Archives):** 끝났거나 안 쓰는 것들의 보관소

폴더 이동 같은 반복 작업이야말로 에이전트에게 위임하기 가장 좋은 일입니다. 나는 **분류 기준 판단과 최종 검수**만 합니다.

### 미션 (20~30분)

1. Day 2에서 만든 PARA 폴더가 잘 있는지 확인합니다. (없거나 빠진 폴더가 있으면 "옵시디언 파라 기법 폴더 만들어줘"로 다시 만듭니다.)
   ```
   볼트의 폴더 구조를 트리로 보여줘
   ```
2. 분류안을 먼저 보고받습니다. (바로 옮기게 하지 않는 것이 포인트입니다.)
   ```
   볼트의 모든 노트를 PARA 기준으로 어디에 배치할지 분류안을 표로 보여줘.
   기준은 '이 노트가 어떤 행동에 필요한가'로 판단해줘.
   ```
3. 분류안을 검수합니다. 애매한 노트는 Resources로 보내는 게 원칙입니다. 확정되면 실행을 지시합니다.
   ```
   좋아, 그 분류안대로 노트를 이동해줘. 이동 후 링크가 깨진 곳이 있는지 확인해서 보고해줘.
   ```
4. 마무리 점검을 합니다.
   ```
   볼트의 최종 폴더 구조를 트리로 보여주고, 허브 노트의 링크가 모두 정상인지 확인해줘
   ```

> **💡 TIP:** PARA의 핵심은 완벽한 분류가 아니라 **유연한 이동**입니다. 프로젝트가 끝나면 "OO 프로젝트 노트들 Archive로 옮겨줘" 한 줄이면 됩니다.

### 완료 체크리스트

- [ ] PARA 폴더 4개 확인 (Day 2에서 생성)
- [ ] 분류안 검수 → 승인 → 실행의 위임 사이클 경험
- [ ] 이동 후 링크 정상 작동 확인

## 6일을 마친 당신에게

이제 서버의 볼트에는 **4단 구조를 갖추고, 링크와 태그로 엮이고, PARA로 정리된** 노트들이 있습니다. 그리고 그보다 중요한 것 — 여러분은 **지시하고, 보고받고, 검수하는** 에이전트 협업 사이클을 6일 내내 반복했습니다. 3차시에서는 이 KB를 에이전트에게 '전수'해서, 여러분 대신 전문가답게 답변하게 만듭니다.

> **한 줄 정리:** 옵시디언은 에이전트가 다루고, 지식의 주인은 나다 — 방향을 정하고(지시), 경험을 주고(재료), 결과를 가리는(검수) 사람이 진짜 전문가다.
